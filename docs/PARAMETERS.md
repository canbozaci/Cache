# Cache Parameter Contract

This document records the current parameter contract for `cache`.

The cache now has width-clean RTL elaboration and scoreboard coverage for selected non-default configurations. The supported matrix is still intentionally narrow and should grow only with regression coverage.

## Top-Level Parameters

| Parameter | Default | Meaning |
| --- | ---: | --- |
| `ADDR_WIDTH` | 19 | CPU/cache byte-address width. |
| `DATA_WIDTH` | 64 | Data-side raw request and response width. |
| `MEM_DATA_WIDTH` | 32 | Native memory-side beat width. |
| `LINE_WIDTH` | 128 | Cache line width. |
| `L1_SET_COUNT` | 64 | Backward-compatible default number of L1 sets. Must be a power of two. |
| `L1_DATA_SET_COUNT` | `L1_SET_COUNT` | Number of data-side L1 sets. Must be a power of two. |
| `L1_INSTR_SET_COUNT` | `L1_SET_COUNT` | Number of instruction-side L1 sets. Must be a power of two. |
| `L2_SET_COUNT` | 256 | Number of L2 sets. Must be a power of two. |
| `MEMORY_BASE_ADDR` | `32'h2000_0000` | Native memory address base added to cache-local addresses. The default preserves the original low cache-local address bits. |

The L1 and L2 way count is fixed at 2 in the current RTL.

## Release Support Matrix

This is the release-facing support claim for the current branch. A configuration is release-supported only when it is listed here and obeys the legal range rules below.

| Area | Release-supported values | Evidence |
| --- | --- | --- |
| `ADDR_WIDTH` | 19, 20 | Directed scoreboard and compile/lint sweeps. |
| `DATA_WIDTH` | 32, 64, 128 | Directed scoreboard and compile/lint sweeps. `DATA_WIDTH=128` is supported only with `LINE_WIDTH=256`. |
| `MEM_DATA_WIDTH` | 32, 64 | Directed scoreboard and compile/lint sweeps. |
| `LINE_WIDTH` | 128, 256 | Directed scoreboard and compile/lint sweeps. |
| `L1_DATA_SET_COUNT` | 16, 32, 64 | Directed set-count tests, split-L1 tests, random scoreboard, and compile/lint sweeps. |
| `L1_INSTR_SET_COUNT` | 16, 32, 64 | Directed set-count tests, split-L1 tests, random scoreboard, and compile/lint sweeps. |
| `L2_SET_COUNT` | 64, 128, 256 | Directed set-count tests, random scoreboard, and compile/lint sweeps. |
| L1/L2 way count | 2 | Fixed RTL architecture. |

Supported combinations are limited to the directed scoreboard configurations below plus legal combinations generated by `make random-scoreboard`. Values outside this matrix may elaborate, but they are not release-supported until they receive directed scoreboard coverage.

Release support assumes the timing and integration contract in `docs/TIMING_CONTRACT.md`, including the single-request line-boundary rule and the documented instruction/data L1 coherency limitation.

## Derived Widths

For the default configuration:

| Derived value | Formula | Value |
| --- | --- | ---: |
| Data-side byte lanes | `DATA_WIDTH / 8` | 8 |
| Memory-side byte lanes | `MEM_DATA_WIDTH / 8` | 4 |
| Line bytes | `LINE_WIDTH / 8` | 16 |
| Memory beats per line | `LINE_WIDTH / MEM_DATA_WIDTH` | 4 |
| Native read burst length | `LINE_WIDTH / MEM_DATA_WIDTH` for line fills, otherwise 1 | 4 |
| Native write burst length | Memory beats touched by data write strobes | 1 to 3 in current directed tests |
| L1 word offset bits | `log2((LINE_WIDTH / 8) / 4)` | 2 |
| Line byte offset bits | `log2(LINE_WIDTH / 8)` | 4 |
| L1 data index width | `log2(L1_DATA_SET_COUNT)` | 6 |
| L1 instruction index width | `log2(L1_INSTR_SET_COUNT)` | 6 |
| L2 index width | `log2(L2_SET_COUNT)` | 8 |
| L1 data tag width | `ADDR_WIDTH - L1_DATA_INDEX_WIDTH - L1_WORD_OFFSET_WIDTH - 2` | 9 |
| L1 instruction tag width | `ADDR_WIDTH - L1_INSTR_INDEX_WIDTH - L1_WORD_OFFSET_WIDTH - 2` | 9 |
| L2 address width | `ADDR_WIDTH - LINE_OFFSET_WIDTH` | 15 |
| L2 tag width | `L2_ADDR_WIDTH - L2_INDEX_WIDTH` | 7 |

## Legal Range Rules

The intended legal range is:

- `ADDR_WIDTH` must be large enough to contain tag, index, word offset, and byte offset fields.
- `DATA_WIDTH`, `MEM_DATA_WIDTH`, and `LINE_WIDTH` must be byte multiples.
- `DATA_WIDTH`, `MEM_DATA_WIDTH`, and `LINE_WIDTH` should be powers of two.
- `LINE_WIDTH` must be an integer multiple of `MEM_DATA_WIDTH`.
- `LINE_WIDTH` must be at least as wide as `DATA_WIDTH`.
- A single data-side request must not cross a cache-line boundary. CPU adaptors must split any wider or unaligned transfer that would cross a line.
- `L1_SET_COUNT`, `L1_DATA_SET_COUNT`, `L1_INSTR_SET_COUNT`, and `L2_SET_COUNT` must be powers of two.
- The derived L1 and L2 index widths must leave at least one tag bit.
- `MEMORY_BASE_ADDR + cache-local address` must fit within the 32-bit native memory address output.

## Remaining Unsupported Claims

Do not claim behavioral support for combinations that are not explicitly covered by scoreboard or directed tests.

Specific remaining risks:

- Fill sequencing now uses a derived memory-beat count and is tested for `MEM_DATA_WIDTH=64` and `LINE_WIDTH=256`.
- Write-through sequencing now uses a derived memory-beat index and is tested for one-beat, two-beat, and three-beat directed writes in the current scoreboard matrix.
- `DATA_WIDTH=128` is behaviorally supported only for the documented `LINE_WIDTH=256` configurations, and only when each request stays within one cache line.
- L1 and L2 replacement behavior is only lightly swept beyond the documented non-default and split L1 set-count cases.
- Configurations outside the explicit scoreboard matrix above are not advertised as behaviorally supported.
